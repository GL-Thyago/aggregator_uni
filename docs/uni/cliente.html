Como integrar seu cassino à Uni

A Uni entrega o catálogo de jogos e a URL para o jogador jogar. O saldo continua no seu sistema. Vocês não falam com o estúdio de jogos — só com a Uni.

Baixar Markdown Baixar HTML

O que vocês fazem

  1. Recebem uma API Key da Uni.
  2. Informam a URL do vosso wallet (saldo do jogador) e um segredo compartilhado.
  3. No site: listar jogos, pedir para abrir um jogo, colocar a launchUrl num iframe (ou nova aba).
  4. No backend: responder saldo e aposta quando a Uni chamar.

Base da API

https://rggames.site/api/v1

Header em todas as chamadas de vocês para a Uni:

X-Api-Key: <a chave que a Uni enviou>

Opcional: POST /auth/token com { "apiKey" } e depois Authorization: Bearer ….

1. Listar jogos

GET https://rggames.site/api/v1/games
X-Api-Key: ca_...

Usem o campo slug para abrir o jogo. Capa: GET https://rggames.site/api/v1/media/cover/{slug}.

Para copiar o catálogo para o vosso banco: GET /api/v1/sync/games.

2. Abrir um jogo

externalUserId é o ID do jogador no vosso cassino. A Uni usa esse ID em todo movimento de saldo.

Teste (homologação):

POST https://rggames.site/api/v1/uni/test/games/{slug}/launch
X-Api-Key: ca_...
Content-Type: application/json

{ "externalUserId": "20419622", "currency": "BRL" }

Produção (dinheiro real):

POST https://rggames.site/api/v1/uni/live/games/{slug}/launch
...

Resposta:

{
  "sessionToken": "uuid",
  "launchUrl": "https://…",
  "balance": 11000.00,
  "expiresAt": "2026-08-29T…"
}

Abram launchUrl no iframe ou em nova aba. Não alterem a URL.

3. Iframe

No Content-Security-Policy do vosso site, em frame-src, liberem o domínio da launchUrl (o host depois de https://, até a primeira /).

Se o CSP bloquear, o iframe fica em branco. Nesse caso o jogo ainda pode abrir em nova aba.

4. Wallet (vocês implementam)

A Uni chama o vosso servidor. Cadastro na Uni:

CampoExemplo
walletUrlhttps://seu-cassino.com/api/casino/wallet
walletSecretmesmo segredo que vocês usam para validar a assinatura

Toda request da Uni traz:

X-Wallet-Signature: HMAC-SHA256(corpo_bruto, walletSecret) em hexadecimal.

Validem no body cru (string do JSON), não no objeto já parseado.

Saldo

POST {walletUrl}/balance

{ "externalUserId": "20419622", "currency": "BRL" }

→ { "balance": 11000.00, "currency": "BRL" }

balance em reais (número), não em centavos.

Aposta e prêmio

POST {walletUrl}/spin

{
  "externalUserId": "20419622",
  "gameSlug": "superHotBingo",
  "betAmount": 0.80,
  "winAmount": 0.40,
  "spinId": "uuid",
  "sessionId": "session-token",
  "currency": "BRL",
  "gameFeeAmount": 0,
  "clientFeeAmount": 0,
  "gameFeePct": 0,
  "clientFeePct": 0
}

→ { "ok": true, "balanceBefore": 11000, "balanceAfter": 10999.60 }
  • Aposta: betAmount maior que zero, winAmount zero → debitar a aposta.
  • Prêmio ou estorno: betAmount zero, winAmount maior que zero → creditar. Isso é válido. Não recusem bet 0 se houver prêmio.
  • Sem saldo: { "ok": false, "error": "Insufficient balance", "balanceBefore": …, "balanceAfter": … }
  • O mesmo spinId não pode debitar duas vezes.
